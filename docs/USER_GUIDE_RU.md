# Руководство пользователя WebsiteAccessibilityMonitor

[English version](USER_GUIDE_EN.md)

## Первый запуск

1. Соберите программу: `cargo build --release`.
2. Запустите `Start.bat` или `target/release/SiteMonitor.exe`.
3. Рядом с исполняемым файлом появится `config.json` со списком сайтов по умолчанию.
4. Через несколько секунд таблица заполнится результатами первой проверки.

Если консоль слишком маленькая, часть сайтов скрывается, а внизу таблицы появляется строка с их числом. Листайте список стрелками или увеличьте окно. Таймлайн аптайма показывается, когда в окне не меньше 28 строк.

## Как читать таблицу

| Колонка | Значение |
|---|---|
| Статус | результат проверки |
| Сайт | адрес из конфигурации |
| IP | адрес, полученный через DNS |
| Код | код ответа HTTP |
| Метод | HEAD или GET |
| Повт | сколько повторов понадобилось |
| мс | время ответа, цвет зависит от скорости |

Над таблицей показаны общие параметры, снизу доступность в процентах, текущая сортировка, подсказки по клавишам и время до следующей проверки.

## Настройки в программе

Нажмите `O`. Стрелки вверх и вниз выбирают строку, стрелки влево и вправо меняют значение, `Enter` открывает ввод текста. Снова `O` сохраняет изменения в `config.json`, `Esc` выходит без сохранения.

В окне настроек доступны:

- интервал, таймаут и число повторов;
- пинг, сбор аптайма, быстрый метод HEAD;
- журнал, экспорт в CSV и пути к файлам;
- вебхуки: токен и чат Telegram, адреса Discord и Slack, порог падений, уведомления о падении и восстановлении;
- прокси: адрес, пользователь, пароль;
- сервер DNS-over-HTTPS.

## Файл config.json

Файл лежит рядом с исполняемым файлом. После правки вручную нажмите `R`.

### monitor_settings

| Поле | По умолчанию | Значение |
|---|---|---|
| `interval` | `60` | секунды между проверками |
| `timeout` | `5` | таймаут соединения в секундах |
| `retries_max` | `2` | число повторов |
| `valid_status_codes` | 200, 201, 202, 204, 300, 301, 302, 303, 307, 308 | коды, считающиеся успехом |
| `warn_status_codes` | 401, 403, 429 | коды со статусом предупреждения |
| `sorted` | `status` | начальная сортировка |
| `ping_enabled` | `true` | пинг хостов |
| `uptime_enabled` | `false` | сбор аптайма за сутки |
| `use_head_first` | `true` | начинать с HEAD |
| `proxy_url`, `proxy_username`, `proxy_password` | пусто | прокси |
| `doh_server` | `https://cloudflare-dns.com/dns-query` | сервер DNS-over-HTTPS |

### Сайты и группы

`websites` содержит простой список адресов. В `website_groups` можно завести группы со своим интервалом и заголовками:

```json
"website_groups": [
  {
    "name": "API",
    "interval": 30,
    "sites": [
      { "url": "https://example.com/health", "headers": { "Accept": "application/json" } }
    ]
  }
]
```

### Уведомления

Блок `webhooks`:

| Поле | Значение |
|---|---|
| `enabled` | общий выключатель |
| `telegram_bot_token`, `telegram_chat_id` | бот и чат Telegram |
| `discord_webhook_url`, `slack_webhook_url` | адреса вебхуков |
| `notify_on_down`, `notify_on_recovery` | о чём сообщать |
| `min_failures_before_alert` | сколько неудач подряд нужно до уведомления, по умолчанию 3 |

Токены и пароль прокси хранятся в `config.json` открытым текстом, поэтому не публикуйте этот файл.

### Журнал, экспорт, цвета

- `Monitor`: `logging_enabled`, `log_file_path`, `log_max_size_mb`, `log_rotate_daily`.
- `csv_export`: `enabled`, `file_path`.
- `uptime_history_path`: файл истории аптайма.
- `color_theme`: цвета для статусов и заголовков, имена вроде `Green` или `Cyan`.

## Частые вопросы

**Пинг не работает.** ICMP реализован только для Windows. На других системах проверяются только HTTP и DNS.

**Сайт открывается в браузере, но программа показывает ошибку.** Некоторые серверы отклоняют HEAD. Программа сама пробует GET, а если код ответа вас устраивает, добавьте его в `valid_status_codes`.

**Сайт получает статус предупреждения.** Его код ответа входит в `warn_status_codes`: обычно это защита от автоматических запросов, а не недоступность.
